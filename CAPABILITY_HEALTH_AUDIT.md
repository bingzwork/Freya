# Freya Capability Health Audit (Post-Repair)

**Audit scope.** This report covers the 42 capabilities registered by the running local Freya installation after the routing, bridge, decision, safety, vision, planning, research, and observability repairs completed for pasted_content_16. Evidence is local-only: focused pytest suites, a permanent 210-case natural-language router matrix (five realistic variants per capability), canonical direct-action checks, and bounded `/api/chat` checks. No external service was contacted during this audit.

The 42 baseline prompts in `tests/test_capability_routing_regression.py` pass **42/42**, and the expanded matrix in `tests/test_pasted16_routing_matrix.py` passes **210/210**. ## Root causes repaired

1. `decision_engine` validated `task` and at least two options, converted conversational strings into canonical `DecisionOption` objects, and returned controlled failures for invalid input.
2. The registration bridge called a static result normalizer as an instance method, causing successful capability actions to be reported as failures; the invocation now uses the static boundary correctly.
3. Conversational input normalization now carries query/task/problem/question/search fields and extracts explicit decision options and local paths without inventing action-specific values.
4. Deterministic capability pre-selection now precedes generic planning/LLM fallback. Safe read-only capabilities return direct routes; unsafe capabilities return an engineering route that remains subject to SafetyGate.
5. Unsafe public capabilities were previously isolated by mutating `auto_discoverable` during startup. That mutation was removed; public mutation capabilities remain discoverable and safety-gated, while internal-only dispatch behavior is still protected by its normal boundary.
6. Generic automation metadata contained broad `file` and `website` tags, creating collisions; those tags were removed. Phrase-specific scoring now lets longer semantic patterns outrank one-word matches.
7. The control parser no longer treats every sentence containing `status` as a control command; explicit control commands remain supported while ordinary system-status questions reach the system capability.
8. Semantic aliases were expanded for the remaining public capabilities and duplicate alias declarations were normalized so the effective runtime dictionary matches source intent.
9. Vision requests using the established `image_path` input now resolve correctly, and every vision result exposes a stable top-level evidence object with source filename/provenance while preserving explicit provider-unavailable errors.
10. `planning_engine.action_create_plan` now passes the supplied context through the existing planner contract instead of referencing an undefined variable; the production action test now completes successfully.
11. The research importer boundary no longer rejects valid provider-ranked results merely because the title/snippet does not repeat query terms; public URL validation and bounded fallback behavior remain intact.
12. Control parsing now distinguishes standalone system controls from capability requests such as pausing a reminder, and strong built-in capability matches are considered before generic explanatory fallback.
13. System metrics rate calculations now fail safely when two collection timestamps are identical, preventing a division-by-zero error during startup or rapid collection.

## Verification and constraints

The changed source files were compiled with the local Python 3.12 environment. The permanent 42-case baseline and 210-case expanded routing matrix passed. The final focused verification group passed with one pre-existing skipped case. Capability/provider/HTTP regressions, learning-distillation runtime tests, foundation/autonomy tests, and production wiring tests passed. `learning_pipeline` is wired to the canonical LearningPipeline and MemoryCoordinator; its internal KnowledgeDistiller, ExperienceDistiller, and SkillDistiller paths are verified, but no separate public `distillation` action is exposed—the public adapter actions remain `reflect`, `consolidate`, and `store_lesson`.

No downloads, installs, package additions, model pulls, browser-driver downloads, external fetches, fake results, audit-prompt special cases, test-only production backdoors, SafetyGate bypasses, or broad success-swallowing exception handlers were used. The ten environment-limited rows remain honestly classified rather than being fabricated green.
